# E Worldwide Consulting website

Marketing website for E Worldwide Consulting (Atlanta, Georgia · United States and South Africa).
Static HTML generated from structured content, plus a small Python server for the contact form.
No Node.js or third-party Python packages are required.

## Quick start

```bash
python3 -I build.py      # generate public/ from templates/ and content/
python3 -I server.py     # http://127.0.0.1:8080
```

Re-run `build.py` after editing anything in `templates/` or `content/`. Changes to `public/assets/` (CSS, JS, images) need no build.

## Project layout

| Path | Purpose |
| --- | --- |
| `content/*.json` | Structured content: site facts, case studies, team, founder milestones, insights |
| `templates/layout.html` | Shared header, navigation, footer, SEO and social metadata |
| `templates/pages/*.html` | Page bodies (16 pages plus the article template) |
| `templates/partials/world-map.svg` | Dotted world map, generated by `scripts/make_map.py` |
| `public/` | The deployable site. HTML, `sitemap.xml` and `robots.txt` are generated; `public/assets/` is hand-written |
| `build.py` | Static site builder (standard library only) |
| `server.py` | Static file server and `POST /api/contact` handler |
| `data/` | Contact form submissions (`submissions.jsonl`). Git-ignored; contains personal data |
| `docs/LAUNCH-CHECKLIST.md` | Facts, approvals, accessibility, security and performance checks before launch |
| `archive/` | Earlier design explorations, not deployed |

## Content management

Content lives in version-controlled JSON so that non-developers can update it with a pull request, and so it can move to a headless CMS later without changing the page designs.

- **Site facts** (`content/site.json`): domain, contact email, founder title, founding year, office details. Each fact has a `verified` flag.
- **Case studies** (`content/case_studies.json`): follow the eight-part structure in `_schema`. Use `"status": "published"` only for approved projects. Placeholder slots appear only in preview builds.
- **Team** (`content/team.json`): real, approved people only. Set `"approved": true` once the person signs off.
- **Founder story** (`content/milestones.json`): add confirmed dates and founder-provided events.
- **Insights** (`content/insights.json`): article HTML, category, summary and publication date.

**Review mode.** While `"review_mode": true` in `content/site.json`, pages show a preview banner, unverified facts are dotted-underlined, and drafts are labeled. Set it to `false` for production. A production build **fails** if any unverified placeholder remains, and it lists the affected pages.

**Moving to a headless CMS.** The JSON shapes map directly to CMS content types (Sanity, Contentful, Strapi and others). Replace `load()` in `build.py` with an API fetch and rebuild on publish via a webhook.

## Contact form

`POST /api/contact` accepts JSON (from the page script) or a standard form post (no-JS fallback, redirects back with `?status=sent`).

- All fields are validated on the server; allowed values for selects are whitelisted.
- Spam protection: hidden honeypot field, minimum 3-second fill time, 5 submissions per IP per 10 minutes, 20 KB body limit. Suspected bots receive a normal response and their submission is discarded.
- Submissions are appended to `data/submissions.jsonl` with owner-only file permissions.
- Optional email forwarding: set environment variables on the server (never in frontend code):

```bash
export CONTACT_SMTP_HOST=smtp.example.com CONTACT_SMTP_PORT=587
export CONTACT_SMTP_USER=... CONTACT_SMTP_PASSWORD=...
export CONTACT_TO=verified-inbox@company-domain CONTACT_FROM=website@company-domain
```

To use a CRM instead, add the call in `send_email()` (or a sibling function) in `server.py`.

## Deployment

### Option A: Linux server (VM) with the included Python server

1. Copy the repository to the server (for example `/srv/ewwc`), set `review_mode` to `false`, set `site_url`, and run `python3 -I build.py`.
2. Run the app as a dedicated user with systemd:

   ```ini
   # /etc/systemd/system/ewwc.service
   [Unit]
   Description=E Worldwide Consulting website
   After=network.target

   [Service]
   User=ewwc
   WorkingDirectory=/srv/ewwc
   Environment=HOST=127.0.0.1 PORT=8080 TRUST_PROXY=1
   EnvironmentFile=-/srv/ewwc/.env
   ExecStart=/usr/bin/python3 -I server.py
   Restart=on-failure

   [Install]
   WantedBy=multi-user.target
   ```

3. Put a TLS-terminating reverse proxy in front (Caddy shown; it obtains certificates automatically):

   ```
   www.your-domain.com {
       encode zstd gzip
       reverse_proxy 127.0.0.1:8080
   }
   your-domain.com {
       redir https://www.your-domain.com{uri} permanent
   }
   ```

   Add `Strict-Transport-Security: max-age=31536000; includeSubDomains` at the proxy once HTTPS is confirmed working.

4. Back up `data/` daily (it is the only stateful directory) and monitor the service with an uptime check on `/` and alerting on `systemctl` failures.

### Option B: Static host + serverless form

Upload `public/` to any static host (Netlify, Vercel, Cloudflare Pages, S3 + CloudFront). Re-implement `/api/contact` as a serverless function using the validation rules in `server.py`, and copy the security headers from `SECURITY_HEADERS` into the host's header configuration.

### Moving to Next.js later

The brief recommends Next.js with TypeScript. This build was made without Node.js on the development machine. The design system (`site.css` tokens), templates and JSON content model translate one-to-one into Next.js components and a CMS; the contact handler becomes a Route Handler.

## Maintenance

- **Dependencies**: none beyond Python 3.10+ and Google Fonts (loaded by the browser).
- **Logs**: the server logs method, path and status only, never form contents.
- **Map**: to regenerate, download Natural Earth `ne_110m_land.geojson` and `ne_110m_admin_0_countries.geojson`, then run `python3 -I scripts/make_map.py <land> <countries>`.
- **Before every release**: work through `docs/LAUNCH-CHECKLIST.md`.
